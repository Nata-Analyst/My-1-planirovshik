# Концепция личного планировщика

## Назначение

Личная веб-страница для фиксации времени, потраченного на задачи в течение семи дней, и оценки доли использованного полезного времени. Пользователь работает на компьютере, выбирает категории из справочника и записывает время. Сравнения плана с фактом, статусов выполнения и переноса незавершённых задач нет.

## Состав проекта

Приложение состоит из трёх файлов:

- `index.html` — структура страницы, вкладки, формы и области графиков.
- `style.css` — оформление, сетка дней, цвета и состояния элементов.
- `script.js` — работа с датами, записями, справочником, расчётами и localStorage.

Страница работает локально в браузере без сервера, базы данных и обязательного подключения к интернету. Внешние библиотеки, шрифты и сервисы не требуются. Графики формируются средствами HTML, CSS и JavaScript.

## Вкладки

### «Планировщик»

В верхней части находятся заголовок, диапазон отображаемых дат и управление периодом. Ниже в одном горизонтальном ряду расположены семь карточек дней. Под карточками находится общий график из семи столбцов и итоговая эффективность периода.

### «Справочник»

Справочник содержит простой список названий категорий. Именно категории используются как выбираемые задачи при добавлении записи в день. Дополнительных полей — описания, цвета категории или плановой длительности — нет.

Пользователь может добавить категорию, переименовать её или удалить. Пустые названия и дубликаты без учёта регистра не допускаются. Переименование обновляет название в связанных записях. При удалении категории существующие записи сохраняются с последним названием; категория перестаёт предлагаться для новых записей.

## Подвижный период из семи дней

При первом открытии показывается текущая календарная неделя с понедельника по воскресенье. Затем пользователь может выбрать любую начальную дату: например, период со вторника по понедельник или со среды по вторник.

Для управления предусмотрены:

- поле выбора начальной даты;
- ползунок сдвига начальной даты по дням;
- кнопки сдвига на один день назад и вперёд;
- кнопка возврата к текущей неделе.

Ползунок позволяет сдвигать период на 31 день в любую сторону относительно выбранной опорной даты. Выбор даты через календарь задаёт новую опорную дату и возвращает ползунок в центр. Это позволяет перейти к любой дате без ограничения истории.

В карточке дня показываются название дня недели и дата. Текущий день выделяется мягким зелёным акцентом. При изменении периода записи остаются привязаны к своим календарным датам: перемещается только отображаемое окно, данные не переносятся и не дублируются.

## Записи времени

В каждой карточке дня есть список записей и кнопка добавления. Для записи выбирается категория из справочника. Одну категорию можно добавлять несколько раз в один день, например для нескольких отдельных занятий.

Поддерживаются два режима ввода времени:

1. **Длительность в часах.** Пользователь вводит положительное число, например `1`, `1,5` или `2.25`. Допускаются десятичная запятая и точка.
2. **Интервал «с … до …».** Пользователь указывает время начала и окончания, а длительность рассчитывается автоматически. В этом режиме поле длительности доступно только для чтения, поэтому расхождения между интервалом и длительностью исключены.

Каждая запись использует один выбранный режим. Запись можно редактировать или удалить; смена режима выполняется при редактировании. При переходе к ручной длительности рассчитанное значение подставляется в поле, а интервал больше не используется в расчётах.

Для однозначного учёта интервал относится к одной календарной дате: окончание должно быть позже начала. Занятие через полночь записывается двумя записями в соответствующих днях; конец суток допускается обозначать как `24:00`. Поля времени реализуются так, чтобы это значение можно было ввести.

Расчёты внутри приложения ведутся в минутах. Длительность в часах при сохранении округляется до ближайшей минуты; значение, округлившееся до нуля, не сохраняется. В интерфейсе длительность показывается в часах с точностью до двух знаков после запятой, без лишних нулей.

Пересекающиеся интервалы разрешены. Сумма учитывает каждую запись полностью, без исключения пересечений: приложение считает записанное пользователем время и не определяет занятость по уникальным минутам суток.

Если справочник пуст, в форме добавления показывается подсказка создать категорию во вкладке «Справочник».

## Расчёты и графики

### Показатели дня

Под списком записей каждого дня располагаются:

- сумма часов всех записей этого дня;
- процент эффективности дня;
- горизонтальный индикатор заполнения.

Формула: `эффективность дня = сумма минут дня / 960 × 100%`, где 960 минут равны 16 часам полезного времени.

Примеры: 4 часа — 25%, 8 часов — 50%, 16 часов — 100%.

### Общий график периода

Ниже семи карточек расположен столбчатый график: один столбец на календарный день. Высота столбца отражает сумму часов этого дня. Подпись содержит день недели и дату, над столбцом показывается количество часов. Шкала общая для всех семи столбцов; её верхняя граница составляет как минимум 16 часов и увеличивается, если есть большее значение. Уровень 16 часов отмечается на графике.

Рядом с графиком показываются суммарные часы и эффективность всего выбранного периода. За 100% принимаются `7 × 16 = 112 часов`.

Формула: `эффективность периода = сумма минут за семь дней / 6720 × 100%`.

Примеры: 28 часов — 25%, 56 часов — 50%, 112 часов — 100%. Показатель периода рассчитывается по всем семи отображаемым дням, включая дни без записей.

Пустой день имеет 0 часов и 0%. Проценты показываются с точностью до одного знака после запятой. До отображения значения не округляются, чтобы не накапливать погрешность.

Если сумма превышает 16 часов за день или 112 часов за период, числовой процент показывается выше 100%. Полоса индикатора заполняется максимум на 100%, а столбцы графика продолжают отражать реальные часы. Это принятое решение для реализации, поскольку отдельное ограничение на превышение не задано.

Все итоги и графики обновляются сразу после добавления, изменения или удаления записи и при переключении дат.

## Внешний вид

Спокойная зелёная палитра: очень светлый зелёный фон, светлые карточки, умеренно зелёные кнопки и индикаторы, тёмный читаемый текст. Мягкие границы, небольшие скругления и ненавязчивые тени помогают отделить дни друг от друга.

Семь дней всегда располагаются в один ряд и имеют одинаковую ширину. При недостаточной ширине окна используется горизонтальная прокрутка, а не перенос дней во второй ряд. Специальная мобильная версия не предусмотрена.

Формы имеют видимые подписи, понятные сообщения об ошибках и доступное управление с клавиатуры. Цвет дополняет числовые подписи, поэтому показатели можно понять и без различения оттенков.

## Хранение данных

Все данные сохраняются в localStorage текущего браузера после каждого изменения. После закрытия страницы и повторного открытия восстанавливаются категории, записи и выбранная начальная дата периода.

Предполагаемая структура состояния:

- версия формата данных;
- справочник категорий со стабильными идентификаторами;
- записи со стабильными идентификаторами, календарной датой, ссылкой на категорию, сохранённым названием категории, режимом ввода и длительностью в минутах;
- начало и окончание интервала для записей в режиме интервала;
- настройки отображаемого периода.

Даты хранятся как локальные календарные строки `YYYY-MM-DD`, без преобразования в UTC. Это исключает смещение записей на соседний день из-за часового пояса.

При первом запуске справочник и дни пустые. Если localStorage недоступен или запись не удалась, страница явно сообщает, что изменения не сохранены. Если сохранённые данные повреждены, приложение показывает ошибку и не перезаписывает их автоматически.

Экспорт, импорт, резервное копирование и синхронизация между устройствами не входят в проект. Очистка данных браузера удаляет сохранённые записи. Надёжность хранения при открытии через `file://` зависит от браузера; это следует проверить в браузере пользователя. Для повторного доступа к данным следует открывать страницу в том же браузере, профиле и по тому же пути.

## Основной сценарий

1. Пользователь открывает страницу и заполняет справочник категорий.
2. На вкладке «Планировщик» выбирает начало нужного семидневного периода.
3. В выбранном дне добавляет запись и выбирает категорию.
4. Вводит длительность либо интервал начала и окончания.
5. После сохранения видит обновлённые часы, эффективность дня и общий график.
6. При следующем открытии продолжает работу с сохранёнными данными.

## Критерии готовности

- Проект реализован в трёх файлах HTML, CSS и JS и работает без сервера и внешних зависимостей.
- На вкладке планировщика отображаются семь последовательных дат в одном ряду.
- Начало периода можно выбрать календарём, ползунком и кнопками сдвига.
- Записи сохраняются за конкретными датами и доступны при возвращении к ним.
- Категории создаются и редактируются в отдельной вкладке.
- Одна категория может встречаться несколько раз в одном дне.
- Ручной ввод часов и автоматический расчёт по интервалу дают согласованные результаты.
- Для каждого дня показываются часы и эффективность относительно 16 часов.
- Общий график содержит семь столбцов, а эффективность периода рассчитывается относительно 112 часов.
- Изменения сохраняются в localStorage и восстанавливаются после перезагрузки страницы.
- Нет сравнения плана и факта, статусов выполнения, переноса задач, мобильной версии и резервного копирования.
