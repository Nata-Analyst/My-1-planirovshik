# Техническое задание: личный планировщик времени

Версия: 1.2. Дата: 26 октября 2026 года. После инженерного ревью и уточнения пользователя: Firefox исключён из целевых браузеров.

## 1. Назначение и приоритет требований

Создать локальное одностраничное приложение на русском языке для одного пользователя. Приложение позволяет вести справочник задач, записывать потраченное на них время за выбранные даты и анализировать использование времени за семь последовательных дней.

Это задание уточняет и заменяет противоречащие ему положения `concept.md`. В частности: использовать термин «задача» вместо «категория»; поддержать интервалы через полночь одной записью; запрещать пересечения интервалов; вместо удаления задач справочника применять архивирование; редактировать записи на месте с автосохранением.

В следующих разделах закреплены также решения для деталей, которые пользователь оставил на усмотрение реализации. Они являются требованиями этой версии, дополнительных вопросов при написании кода не требуют.

## 2. Технические границы

### 2.1. Поставка и запуск

Работающее приложение состоит ровно из трёх файлов в одной папке:

| Файл | Назначение |
| --- | --- |
| `index.html` | Разметка, подключение CSS и обычного JS-скрипта с `defer` |
| `style.css` | Все стили интерфейса |
| `script.js` | Вся логика, расчёты, графики и хранение |

Запуск — двойным щелчком по `index.html`, через `file://`. Не использовать сборщик, сервер, API, базу данных, CDN, внешние шрифты, внешние изображения, пакеты, ES-модули или загрузку локальных ресурсов через `fetch`. Кодировка файлов — UTF-8; язык документа — `ru`. Документы `concept.md` и `tz.md` не являются файлами приложения.

Целевые браузеры для проверки: настольные Chrome и Edge, актуальные стабильные версии на момент реализации. Firefox исключён по прямому указанию пользователя: поддержка и проверка этого браузера не требуются. Требование к работе в конкретном целевом браузере через `file://` проверяется фактическим запуском и сохранением данных, а не предполагается.

### 2.2. Пользователь и данные

Одна роль — владелец локальных данных. Он может выполнять все действия приложения без регистрации и входа. Данные доступны только в текущем браузере и профиле, в пределах доступного странице localStorage. Другой браузер имеет отдельные данные, даже на том же компьютере. Автоматического переноса между браузерами нет.

Одновременное редактирование в нескольких вкладках или браузерах не является поддерживаемым сценарием. Синхронизацию и слияние конфликтов не реализовывать. При получении события `storage` для ключа приложения от другой вкладки заблокировать изменения и показать встроенное уведомление «Данные изменены в другой вкладке. Перезагрузите страницу» с кнопкой перезагрузки, чтобы не перезаписать чужие изменения.

### 2.3. Вне объёма

Нет авторизации, совместной работы, уведомлений, таймера, статусов выполнения, плановой длительности, сравнения плана с фактом, повторяющихся задач, автоматического переноса, копирования или перемещения записей, ручной сортировки, поиска, фильтрации, экспорта, импорта, резервных копий, очистки всей истории, тёмной темы и специальной мобильной версии.

## 3. Термины

| Термин | Определение |
| --- | --- |
| Задача | Именованный элемент справочника, например «Подготовка отчёта» или «Спорт» |
| Запись | Одно занятие выбранной задачей, привязанное к дате и имеющее длительность |
| Период | Семь последовательных календарных дат, начиная с выбранной даты |
| Полезное время | Фиксированная база эффективности: 16 часов в день и 112 часов за период |
| Архивная задача | Задача, доступная в истории и справочнике, но недоступная для новых записей |
| Черновик | Ещё не прошедшие валидацию поля формы, которые не входят в сохранённые итоги |

Отдельной сущности «категория» нет. Упомянутый пользователем график по категориям называется в интерфейсе «По задачам».

## 4. Структура экрана

Две внутренние вкладки: «Планировщик» и «Справочник задач». Переключение не открывает отдельную страницу и не перезагружает документ. При запуске открывается «Планировщик».

Постоянно доступна ненавязчивая строка состояния сохранения: «Все изменения сохранены», «Сохранение…», «Есть незавершённые изменения» или конкретная ошибка. Первый запуск дополнительно показывает закрываемую подсказку «Данные хранятся только в этом браузере. В другом браузере будет отдельный список». После закрытия подсказка больше не появляется в этом профиле.

Порядок блоков вкладки «Планировщик»:

1. Заголовок и выбранный диапазон дат.
2. Выбор начала периода, кнопки сдвига и ползунок.
3. Семь карточек дней в одном горизонтальном ряду.
4. Общие часы и эффективность периода.
5. Общий график с переключателем «По дням» / «По задачам».
6. Таблица итогов по задачам за период.

## 5. Даты и навигация

### 5.1. Первый и последующие запуски

При отсутствии сохранённых настроек начало периода — понедельник текущей локальной календарной недели. Воскресенье считается последним днём недели. Сегодня определяется по локальным настройкам компьютера; пояс не фиксировать в коде.

При следующем запуске восстановить последнее начало периода, опорную дату ползунка и выбранный режим графика. Завершение периода всегда вычислять как начало плюс шесть календарных дней.

### 5.2. Управление

| Элемент | Поведение |
| --- | --- |
| Поле «Начало периода» | Выбор любой допустимой даты задаёт начало, пересчитывает следующие шесть дней, устанавливает опору ползунка в выбранную дату и смещение в 0 |
| Ползунок | Целое смещение от −31 до +31 дня, шаг 1; начало равно опорной дате плюс смещение |
| «Предыдущий день» / «Следующий день» | Сдвигают начало на один день; устанавливают новую опору в полученное начало и смещение в 0 |
| «Текущая неделя» | Устанавливает понедельник текущей недели, новую опору и смещение 0 |

Поле даты всегда отображает фактическое начало периода, в том числе при движении ползунка. Рядом с ползунком показывать его смещение и понятное направление. Графики и карточки перестраивать при изменении значения ползунка без отдельной кнопки применения.

Фразу «автоматический сдвиг на 7 дней, если меняется выбор начала недели» реализовать как автоматическое обновление всего семидневного окна от выбранного начала. Например, при выборе среды 28.10.2026 показать 28.10–03.11.2026. Дополнительного автоматического прибавления семи дней и кнопок ±7 дней нет.

Все даты хранить как строки `YYYY-MM-DD`. Для прибавления дней использовать календарную арифметику с учётом месяцев, годов и високосных лет; не прибавлять фиксированные 86 400 000 мс к локальной полуночи. Не получать календарную дату через `toISOString()`. Диапазон поддерживаемых дат: 01.01.1900–31.12.9999; начало периода — не позднее 25.12.9999. Недоступные сдвиги у границ блокировать.

## 6. Справочник задач

### 6.1. Состав и отображение

Задача имеет название и состояние «активная» / «архивная». Идентификатор стабилен и не зависит от названия. Не предусматривать описание, плановую длительность или отдельное поле категории.

Активные задачи показывать первыми в порядке создания; архивные — затем, тоже в порядке создания. Архивные строки имеют светло-серый фон, приглушённый текст и текстовую метку «В архиве». Не скрывать их и не удалять физически.

### 6.2. Действия

- Добавление: поле названия и кнопка «Добавить задачу»; Enter эквивалентен кнопке. После успешного добавления очистить поле и оставить на нём фокус.
- Переименование: редактирование названия на месте с автосохранением. Новое имя отображается во всех старых записях и отчётах, включая архивную задачу.
- Архивирование: кнопка «В архив», затем подтверждение внутри той же строки. Существующие записи и часы сохраняются. Для новых записей задача больше не предлагается.
- Восстановление: кнопка «Восстановить» в архивной строке, без подтверждения. Задача снова доступна для выбора.

Названия: после обрезки пробелов по краям от 1 до 120 символов. Пустое название запрещено. Уникальность проверяется среди всех задач, включая архивные: Unicode-нормализация NFC, замена последовательностей пробельных символов одним пробелом, сравнение без учёта регистра. Сохранённое имя также привести к NFC и одиночным пробелам. При совпадении с архивной задачей показать «Такая задача уже есть в архиве. Восстановите её». Создание дубликата запрещено.

Если справочник пуст, показать «Добавьте первую задачу, чтобы записывать время». Если все задачи архивные — «Добавьте задачу или восстановите задачу из архива».

## 7. Карточка дня и записи

### 7.1. Карточка

Карточка содержит полное название дня недели, дату, метку «Сегодня» для текущей даты, список записей, кнопку «Добавить запись» и дневные итоги. Пустое состояние: «Записей пока нет».

Каждая запись содержит:

- выбор задачи из справочника;
- переключатель «Часы» / «Интервал»;
- поля выбранного режима и длительность;
- кнопку раскрытия комментария «+» / «−» с поясняющей доступной подписью;
- кнопку удаления.

Все поля редактируются непосредственно в карточке. Запрещены модальные окна, `alert`, `prompt` и `confirm`. Подтверждения и ошибки показывать встроенными блоками.

### 7.2. Новая запись

Нажатие «Добавить запись» создаёт локальную форму-черновик в выбранном дне. Начальное состояние: задача не выбрана, режим «Часы», длительность пустая, комментарий свёрнут. Фокус — на выборе задачи. Допускается один новый черновик на день; повторное нажатие фокусирует его.

Активных задач нет — вместо формы показать подсказку и ссылку-кнопку «Открыть справочник». Переход открывает соответствующую вкладку.

Новый черновик сохраняется как запись только после выбора задачи и ввода корректного времени. До этого он не влияет на графики. Есть действие «Отменить добавление». Отмена несохранённого черновика не требует подтверждения.

Задачу можно добавлять несколько раз в один день при соблюдении правил пересечений интервалов.

### 7.3. Ручная длительность

В режиме «Часы» есть одно поле с подписью «Длительность» и подсказкой «Например: 1,5 или 1:30». Принимать два однозначных формата: десятичные часы и `Ч:ММ`. Для десятичных часов принимать запятую и точку, например `1`, `1,5`, `2.25`, до четырёх дробных знаков; `.5` и `,5` трактовать как 0,5. Для `Ч:ММ` часы — целое число от 0 до 24, минуты — ровно две цифры от 00 до 59; при 24 часах допустимо только `24:00`. Здесь `1:30` означает длительность 90 минут, а не время суток; `0:01` — 1 минуту. Пробелы по краям игнорировать. Не принимать отрицательные числа, экспоненциальную запись, смешанный формат `1,5:30` и произвольный текст. Естественный ввод вида «1ч 15м» не реализовывать.

Десятичные часы переводить в минуты по формуле `Math.round(hours * 60)`, формат `Ч:ММ` — по формуле `hours * 60 + minutes`. Сохраняемое значение — целое от 1 до 1440 минут включительно. Если после округления получилось 0, показать ошибку «Минимальная длительность — 1 минута». Значение больше 24 часов запрещено для одной записи; дневная сумма при этом может превышать 24 часа, поскольку ручные записи не задают интервалы занятости. После завершения редактирования отображать длительность в точном формате `Ч:ММ`, не менять формат и курсор во время набора.

Ручная запись не имеет времени начала, не участвует в проверке пересечений и показывается после записей с интервалами. Это необходимо для сохранения обоих способов ввода без выдумывания времени начала.

### 7.4. Интервал и переход через полночь

В режиме «Интервал» вводятся «С» и «До» в 24-часовом формате `HH:MM` с точностью до минуты. Использовать нативные `input type="time"` с `step="60"`; оба значения находятся в диапазоне `00:00`–`23:59`. Значение `24:00` для времени суток не поддерживается. Окончание в полночь задаётся как `00:00` следующего дня по правилу ниже. Формат ручной длительности `24:00` из раздела 7.3 — другая сущность, его это ограничение не касается.

- Окончание позже начала: интервал внутри выбранной даты.
- Окончание раньше начала: окончание на следующий календарный день.
- Начало равно окончанию: ошибка «Начало и окончание совпадают»; не трактовать как сутки.
- Пример `23:00–01:30`: одна запись длительностью 150 минут. Под полями показать «До 01:30 следующего дня» с датой окончания.
- Пример `23:00–00:00`: 60 минут, окончание в полночь следующего дня. Ровно 24 часа можно записать ручной длительностью `24:00`; одинаковые начало и конец интервала по-прежнему запрещены.

Расчёт длительности выполняется автоматически; результат не редактируется вручную. Интервал не превышает 24 часов. Переход на следующий день за пределы 31.12.9999 запрещён.

**Правило отнесения часов:** запись хранится одна, но её минуты для статистики распределяются по фактическим календарным дням. Запись `26.10 23:00–27.10 01:30` даёт 60 минут дню 26.10 и 90 минут дню 27.10. Полная редактируемая запись находится только в карточке даты начала. В следующем дне показывать компактную строку «Продолжение: Название — 00:00–01:30, 1 ч 30 мин» с датой начала и действием «К записи». Строка продолжения не является второй записью и не редактируется отдельно. Если начало вне видимого периода, действие «К записи» переводит начало периода на дату исходной записи с соблюдением защиты черновиков из раздела 8. Если дата начала уже видна — прокрутить к строке и сфокусировать её. Продолжение при нулевой длительности после полуночи не показывать. У исходной строки явно подписывать «Всего» и «В этот день», если эти величины отличаются.

На границе периода учитывать только минуты, попавшие в семь выбранных дат. Поэтому анализировать также интервалы, начавшиеся накануне первой даты. Минуты за пределами периода в его итог не входят. Ручные длительности целиком относятся к указанной дате: без интервала распределить их иначе невозможно. В статистике, таблице, подсказках и обоих режимах графика использовать одно и то же распределение. Суммы по дням должны точно совпадать с суммами по задачам; продолжение не должно повторно добавлять полную длительность записи.

### 7.5. Запрет пересечений

Проверять интервал против всех сохранённых интервальных записей всех задач за любые даты, включая даты вне видимого периода. Собственную предыдущую версию при редактировании исключать.

Представить начало и конец как номера календарных минут: порядковый номер даты × 1440 + минута суток; при переходе через полночь прибавить сутки к концу. Не использовать локальные миллисекунды для длительности, чтобы перевод часов не менял введённое число минут.

Пересечение есть, когда `newStart < existingEnd && newEnd > existingStart`. Общая граница допустима: `09:00–10:00` и `10:00–11:00` не пересекаются. Интервалы разных задач также не могут пересекаться.

При конфликте показать под полями «Интервал пересекается с записью “Название”, ДД.ММ.ГГГГ, ЧЧ:ММ–ЧЧ:ММ». Новый интервал не сохранять; старое корректное значение и итоги остаются действующими. Указать конфликт с соседним днём, даже если его карточка не видна.

### 7.6. Смена режима

При переходе из интервала в часы подставить текущую рассчитанную длительность в точном формате `Ч:ММ`, например `1:01`. Сохранить исходное целое количество минут без округления. После корректного сохранения ручного режима удалить начало и конец интервала из записи. Для ночного интервала показать перед сменой режима встроенное пояснение «Без интервала всё время будет учтено в дате записи»; смена режима переносит его статистические минуты на дату начала, не создавая дополнительных записей.

При переходе из часов в интервал оставить поля времени пустыми. До ввода обоих корректных значений хранить предыдущую версию записи. Возврат к сохранённому режиму отменяет несохранённые поля смены режима.

### 7.7. Порядок записей

Сначала строки продолжения ночных интервалов, если они есть, затем записи с интервалами по времени начала по возрастанию. При равенстве — по времени создания и идентификатору. Затем ручные длительности по времени создания и идентификатору. После успешного сохранения переставлять запись только при уходе фокуса за пределы её строки, чтобы форма не перемещалась под курсором. Новый черновик показывать внизу до первого сохранения и выхода из формы.

### 7.8. Комментарии

Комментарий необязательный, обычный многострочный текст длиной до 2000 символов. Под записью всегда доступен «+»; после раскрытия он меняется на «−». У заполненного комментария рядом с кнопкой есть текст «Есть комментарий», но сам текст скрыт.

При открытии страницы, переходе между вкладками или смене периода все комментарии свёрнуты. В пределах текущего отображения изменение соседней записи или графика не должно сворачивать открытый комментарий. Состояние раскрытия хранить только в памяти. Текст комментария сохранять автоматически. Закрытие комментария не удаляет текст. Пустой комментарий сохранять как пустую строку.

### 7.9. Удаление записи

Показать внутри строки «Удалить эту запись?» и кнопки «Удалить» / «Отмена». Только подтверждение удаляет запись из хранилища и пересчитывает итоги. При отмене ничего не меняется. Повторное подтверждение не должно удалять другую запись. Восстановление удалённой записи не предусмотрено.

## 8. Автосохранение и черновики

Поля ввода изменяют черновик интерфейса, валидация выполняется в памяти и не обращается к localStorage. Физическое сохранение всех изменённых корректных форм объединять в одну запись состояния после 1500 мс без ввода (trailing debounce). Не сериализовать и не записывать JSON на каждом нажатии клавиши. При выходе фокуса за пределы формы записи или строки задачи выполнять сохранение немедленно; переход между полями одной формы не должен преждевременно фиксировать неполный интервал. Выбор задачи в полностью корректной форме, добавление задачи, удаление с подтверждением, архивирование и восстановление сохранять сразу. Кнопки «Сохранить» нет. Сохранение только на `blur` не подходит: корректный ввод должен сохраняться и при оставшемся в поле фокусе.

Изменения ползунка отображать сразу, а настройки периода сохранять объединённо после 300 мс без движения; на завершении перетаскивания выполнить сохранение сразу. При переходе на другую вкладку приложения и закрытии страницы выполнить принудительное сохранение ожидающих корректных изменений. Не записывать состояние, если сохраняемые данные не изменились. Не перерисовывать все карточки при каждом символе комментария.

Для незавершённого нового черновика показывать нейтральную подсказку о недостающих полях; для неверного формата, отрицательного значения или пересечения — явную ошибку. Для существующей записи недопустимые изменения не заменяют ранее сохранённые данные. Графики всегда строятся по сохранённым версиям, а не по черновикам.

При переходе на другую вкладку приложения или к другому периоду принудительно сохранить все корректные черновики. Если остаются незавершённые или ошибочные изменения, отложить переход и показать встроенный блок «Есть несохранённые поля. Исправьте их или отмените изменения» с действиями «Остаться» и «Отменить изменения и перейти». Последнее отбрасывает только несохранённые правки, сохраняя уже записанные версии. Целевой переход запомнить до выбора действия.

При закрытии браузера вызвать доступный `beforeunload` только при наличии несохранённых правок; стандартный диалог браузера здесь допустим. Гарантировать восстановление незавершённых черновиков после закрытия не требуется. При уходе со страницы корректные изменения, ожидающие debounce, попытаться сохранить синхронно.

## 9. Итоги и графики

### 9.1. Формулы

Пусть `dayMinutes` — сумма минут, отнесённых к выбранной календарной дате по разделу 7.4, а `periodMinutes` — сумма `dayMinutes` за семь выбранных дат. Для интервала использовать длину пересечения с календарными границами дня; для ручной длительности — всю длительность только на её дате. Вычисление: `max(0, min(entryEnd, dayEnd) - max(entryStart, dayStart))` в целых календарных минутах. При `entryEnd == dayStart` вклад равен нулю.

| Показатель | Формула |
| --- | --- |
| Часы дня | `dayMinutes / 60` |
| Эффективность дня | `dayMinutes / 960 * 100` |
| Часы периода | `periodMinutes / 60` |
| Эффективность периода | `periodMinutes / 6720 * 100` |
| Часы задачи за день | Сумма минут данной задачи, попавших в этот календарный день, / 60 |
| Часы задачи за период | Сумма её минут за семь дат / 60 |

Промежуточные суммы считать в целых минутах. Часы выводить с максимум двумя десятичными знаками, проценты — с максимум одним, без лишних нулей, с русской десятичной запятой. Для каждой записи дополнительно показывать точное представление, например «1 ч 1 мин», чтобы округлённые `1,02 ч` не скрывали минутную точность.

День без записей: `0 ч`, `0%`. Пустые дни входят в базу периода. Числовые проценты не ограничивать 100%. Полоса дневного индикатора: `min(100, efficiency)` процентов ширины.

### 9.2. График «По дням»

Семь вертикальных столбцов, по одному на дату, в хронологическом порядке. Ось X — сокращённый день недели и дата; Y — часы. Над столбцами — часы. У нулевого дня остаётся подпись и нулевая отметка.

Верхняя граница Y: `max(16, ceil(maxDayHours / 4) * 4)`. Деления через 4 часа, отметка 16 часов с подписью «16 ч». Высота отражает реальные часы, включая превышение 16. Не обрезать столбцы на уровне 100%.

### 9.3. График «По задачам»

Те же семь дневных столбцов, каждый составлен из сегментов задач. Сумма сегментов равна общей длительности дня. Масштаб, порядок дат и линия 16 часов совпадают с режимом «По дням».

Показывать только задачи с ненулевым временем в периоде, включая архивные. Порядок сегментов и легенды: по убыванию общего времени задачи за период, при равенстве — название по русской локали, затем идентификатор. Цвет задачи стабилен и выводится из её идентификатора, поэтому не меняется при переименовании или смене периода. Использовать спокойные зелёные, шалфейные и бирюзовые оттенки; соседние сегменты отделять тонкой границей. Различение поддерживается текстовой легендой и таблицей, а не только цветом.

При наведении или фокусе на сегмент показывать встроенную подсказку: дата, задача, часы и точные минуты. Нулевые сегменты не рисовать. Легенда не является фильтром и не скрывает задачи. Переключение режима не меняет данные и итоги.

### 9.4. Таблица по задачам

Под графиком в обоих режимах отображать таблицу: «Задача», семь столбцов дат, «Всего, ч». Порядок задач как в легенде. Нулевые значения показывать как `0`; архивные задачи помечать текстом «В архиве». Последняя строка «Всего» содержит итоги по дням и периоду. Если записей нет — график остаётся с семью нулевыми днями, а вместо строк задач показать «В этом периоде пока нет записей».

Среднее за день, самый загруженный день и дополнительные метрики не выводить.

## 10. Архив и исторические записи

Записи ссылаются на задачу по стабильному ID. Название всегда берётся из справочника, поэтому переименование сразу обновляет историю и отчёты. Задачи физически не удаляются, дополнительный снимок названия в записи не нужен.

В старой записи с архивной задачей показывать текущее название и метку «В архиве». При редактировании любой уже сохранённой записи под выбором задачи доступен выключенный по умолчанию переключатель «Показать архивные задачи». Во включённом состоянии он позволяет переназначить запись на любую архивную задачу, не восстанавливая её в справочнике. Текущая архивная задача остаётся видимой и выбранной при любом состоянии переключателя. Архивные варианты помечать «В архиве». Для новых черновиков этот переключатель отсутствует, доступны только активные задачи. Изменять длительность, интервал и комментарий существующей архивной записи можно. Состояние переключателя не сохранять между открытиями страницы.

Архивирование не удаляет часы, не исключает задачу из графиков и не меняет её цвет. Восстановление возвращает ту же задачу с тем же ID.

## 11. Модель данных и localStorage

Использовать единственный основной ключ `personalTimePlanner.state.v1` и JSON следующей структуры. Пример отражает формат, но не должен загружаться как демонстрационные данные:

```json
{
  "schemaVersion": 1,
  "revision": 1,
  "updatedAt": "2026-10-26T09:00:00.000Z",
  "tasks": [
    {
      "id": "task-unique-id",
      "name": "Подготовка отчёта",
      "archived": false,
      "createdAt": "2026-10-26T08:00:00.000Z",
      "updatedAt": "2026-10-26T08:00:00.000Z"
    }
  ],
  "entries": [
    {
      "id": "entry-unique-id",
      "taskId": "task-unique-id",
      "date": "2026-10-26",
      "mode": "interval",
      "durationMinutes": 150,
      "startTime": "23:00",
      "endTime": "01:30",
      "endsNextDay": true,
      "comment": "Завершила расчёты",
      "createdAt": "2026-10-26T08:01:00.000Z",
      "updatedAt": "2026-10-26T09:00:00.000Z"
    }
  ],
  "settings": {
    "periodStart": "2026-10-26",
    "sliderAnchorDate": "2026-10-26",
    "sliderOffsetDays": 0,
    "chartMode": "days",
    "storageNoticeDismissed": false
  }
}
```

Для `mode: "duration"`: `startTime` и `endTime` равны `null`, `endsNextDay` равно `false`. Для интервала `endsNextDay` истинно только при окончании меньше начала; длительность и флаг должны соответствовать полям времени. Начало и конец интервала не принимают `24:00`. Для графика `chartMode` равен `days` или `tasks`. Распределение ночных минут, строки продолжения и итоги являются вычисляемыми представлениями, не дополнительными объектами в хранилище.

ID генерировать локально, не переиспользовать; предусмотреть вариант без `crypto.randomUUID`, если метод недоступен при локальном запуске. `createdAt`, `updatedAt` — UTC-метки технического времени, они не определяют календарную дату записи. `revision` увеличивать после каждой успешной записи состояния.

На старте читать и проверять JSON: версию, типы полей, допустимость дат, уникальность ID, ссылки на задачи, длины строк, длительности, соответствие интервалов и отсутствие их пересечений. Не исправлять повреждённые данные молча. При неподдерживаемой версии или нарушении структуры показать ошибку и заблокировать изменения; исходную строку localStorage не заменять.

При сохранении сначала создать и проверить новое состояние, затем вызвать `localStorage.setItem`. Только после успешной записи принять его как сохранённое, обновить итоги и статус. При исключении предыдущая сохранённая версия и итоги остаются действующими, введённые поля остаются в интерфейсе для повторной попытки. Показывать «Не удалось сохранить изменения в этом браузере» и встроенную кнопку «Повторить сохранение». Не выводить ложное «Сохранено».

При первом запуске проверить доступность хранилища через пробную запись и удаление отдельного временного ключа, не затрагивая пользовательские данные. Если доступ запрещён, показать объяснение и заблокировать редактирование. Переполнение квоты обрабатывать отдельно по разделу 11.1, не приравнивать его к запрету доступа. Если чтение существующих данных возможно, разрешить их просмотр. Не предлагать сброс данных и не очищать localStorage приложения автоматически.

### 11.1. Переполнение и ограничения объёма

Отдельно распознавать `QuotaExceededError` при пробной и основной записи. Не полагаться на фиксированную доступную квоту и не обещать точное количество оставшихся записей. При переполнении показать «Хранилище браузера заполнено. Последние изменения не сохранены. Можно отменить их и удалить ненужные записи или сократить комментарии». Сохранённые данные, включая историю, не удалять и не обрезать автоматически; не очищать данные других приложений и не вызывать `localStorage.clear()`.

Не блокировать просмотр и попытки уменьшить состояние. После явной отмены несохранённых правок разрешать удаление записей с подтверждением и сокращение комментариев. Эти операции также проходят обычную запись через `try/catch`. При успешном сохранении снять предупреждение. Архивирование само по себе не освобождает место, поскольку задача сохраняется. Повторная попытка без освобождения места может снова завершиться ошибкой; это не повод показывать успех.

Если пробная запись не удалась из-за квоты, но основное состояние читается и валидно, открыть его и разрешить операции уменьшения по правилам выше. Отличать этот случай от запрета доступа к хранилищу. Оценивать размер сериализованного состояния приблизительно как `2 * json.length` байт, показывать его в МиБ в справочной строке хранения и при оценке от 4 МиБ выводить ненавязчивое предупреждение «Объём данных велик; доступный лимит зависит от браузера». Это ориентир, не гарантированная граница квоты и не условие запрета записи.

### 11.2. Производительность хранения и расчётов

Оставить единый ключ: для локального личного приложения это упрощает согласованную замену состояния. Разбиение по ключам не вводить без измеренного основания, поскольку оно потребует отдельной стратегии частичных сбоев. JSON разбирать и полностью валидировать один раз при запуске; в рабочей сессии использовать состояние в памяти. Не выполнять `getItem` и `JSON.parse` для каждого поля или каждого пересчёта графика. Сериализовать только при фактической объединённой записи по разделу 8.

Для отображения поддерживать производные индексы записей по датам и задачам. Для ночных записей учитывать соседний день. Начальную проверку пересечений выполнять сортировкой интервалов и последовательным проходом, а не попарным сравнением всех записей. Индексы обновлять после успешного изменения, не хранить их вторым источником истины в localStorage. DOM создавать только для видимого периода, справочника и текущей сводки, не для всей истории.

Проверить объём на синтетическом наборе: 5000 записей по 5 записей на 1000 последовательных дат, 50 задач, комментарий по 100 символов; ID задач распределены циклически, интервалы каждого дня непересекающиеся, например пять последовательных часовых интервалов с 08:00. Набор создаётся только для проверки, не включается в начальные данные продукта. На компьютере проверки измерить не менее пяти переключений периода и пяти сохранений: целевой максимум — 200 мс от изменения даты до завершения перерисовки, 100 мс на сериализацию и `setItem`, без учёта задержки debounce. Указать браузер, компьютер и фактические измерения в отчёте. Если целевые показатели не достигнуты, оптимизировать и повторить измерение; не объявлять неизбежным зависание «через год» без измерений. Если набор превышает квоту конкретного браузера, отдельно зафиксировать ограничение, проверить обработку квоты и измерить операции на максимально поместившемся наборе с указанием размера.

Все данные остаются локальными. В интерфейсе справки кратко указать: очистка данных браузера может удалить записи; другой браузер или профиль имеет отдельное хранилище; после перемещения файла доступ к прежнему хранилищу может измениться. Не обещать синхронизацию или резервирование.

## 13. Внешний вид и удобство

Основной сценарий — настольный экран. Проверить минимум 1366×768 и 1920×1080 при масштабе 100%. Семь карточек всегда в одном ряду: сетка `repeat(7, minmax(170px, 1fr))`, промежутки 8 px, внешние горизонтальные отступы основного контейнера 16 px. При ширине окна 1366 px все семь дней должны помещаться без горизонтальной прокрутки недели. Поля внутри карточки размещать вертикально или компактными строками по доступной ширине; не делать семь фиксированных колонок по 210 px. Если ширина области недели меньше 1238 px (7 × 170 + 6 × 8), включать горизонтальную прокрутку только этой области. Дни не переносить во второй ряд. Проверять длинные названия: переносить текст, применять `min-width: 0`, не допускать расширения сетки содержимым. Таблица сводки при необходимости имеет собственную горизонтальную прокрутку. Высоты карточек выровнять по самой высокой; дневные итоги располагать в нижней части. Страница прокручивается вертикально целиком; не создавать отдельную вертикальную прокрутку каждого дня.

Исходная палитра: фон `#F3F8F1`, карточки `#FFFFFF`, лёгкий зелёный `#E5F1DF`, основной зелёный `#4F7D52`, текст `#203627`, границы `#D4E2CF`, архив `#EEEEEE`. Допускается корректировка оттенков для читаемости. Ошибки оформлять текстом и умеренным красным акцентом, не одним цветом.

Системный шрифт, основной размер не менее 14 px; компактные отступы без наложения элементов. Кнопки имеют видимый фокус, подписи полей связаны с полями. Иконки `+`, `−`, удаления и навигации имеют текстовые доступные имена. Ошибки связаны с полями, статус сохранения объявляется через ненавязчивый `aria-live`. Вкладки, формы и графические подсказки доступны с клавиатуры. Перерисовка не сбрасывает фокус, выделение текста и позицию прокрутки.

Пользовательский текст выводить как текст, а не HTML: строка `<script>` в названии или комментарии не исполняется и отображается буквально. Не использовать `eval` и не вставлять пользовательские строки через `innerHTML`.

Графики реализовать встроенным SVG или HTML/CSS, без внешних библиотек. Таблица остаётся текстовой альтернативой графику. Не использовать внешние сетевые запросы, аналитику и телеметрию.

## 15. Указания для реализации и завершения

В `script.js` логически отделить календарные функции, валидацию, работу с хранилищем, вычисление итогов и отображение. Использовать обычный скрипт со строгим режимом и изолированной областью видимости (например, IIFE), небольшие функции и внутренние объекты по ответственности; один файл не означает одну большую функцию или глобальные переменные. Ограничение ES-модулей обусловлено запуском через `file://`, а не отказом от разделения логики. Единственный источник сохранённых данных — валидное состояние приложения; черновики и раскрытые комментарии хранить отдельно. Не вычислять итоги чтением текста из DOM.

В первую очередь проверить функции календаря, расчёта интервалов, пересечений, сумм и восстановления состояния. Затем пройти сценарии и приёмочные проверки. Для ошибок достаточно конкретного текста рядом с соответствующим полем или блоком; не создавать журнал технических подробностей в пользовательском интерфейсе.

Реализация считается завершённой, когда доступны все действия и сценарии этого задания, выполнены приёмочные проверки, отсутствуют ошибки JavaScript при штатной работе, а локальное сохранение подтверждено перезагрузкой. В отчёте о реализации назвать фактически проверенные браузеры и проверки; непроверенные условия не объявлять выполненными.

На текущем этапе создаётся только этот документ. Написание HTML, CSS и JS данным этапом не предусмотрено.

## 16. Решения по инженерному ревью

| Предложение | Решение и причина |
| --- | --- |
| Экспорт и импорт JSON | Не включать в текущую версию: пользователь прямо исключил резервное копирование. Риск потери локальных данных реален, но не отменяет согласованную границу продукта. Возможное расширение требует отдельного решения пользователя. Очистка обычного кэша и очистка данных сайта — разные действия; не утверждать, что любая очистка кэша обязательно удаляет localStorage |
| Обработка лимита localStorage | Принято: отдельный сценарий квоты, сохранение предыдущих данных, возможность уменьшить объём и повторить запись, приблизительный индикатор размера |
| Разбиение единого JSON ради скорости | Пока не принято; вместо предположения о неизбежных зависаниях заданы замеры, индексы, разбор JSON только при старте и объединение записей. Сохраняется простая согласованная замена состояния |
| Распределение ночных часов | Принято: одна запись в хранении и редактировании, календарное распределение минут в аналитике, строка продолжения и корректная обработка границы периода |
| Удобная ручная длительность | Принято: `Ч:ММ` наряду с десятичными часами; естественный язык не нужен |
| Убрать обязательный горизонтальный скролл на обычном экране | Принято частично: уменьшена минимальная ширина, задано размещение без прокрутки на 1366 px; один ряд остаётся требованием пользователя, на более узких окнах прокрутка допустима |
| Записывать только на blur | Принято частично: debounce 1500 мс, объединённые записи и немедленная фиксация при выходе из формы; автосохранение при паузе оставлено, чтобы не терять ввод с оставшимся в поле фокусом |
| Выбор другой архивной задачи | Принято для редактирования сохранённых записей через явный переключатель; новые записи по-прежнему используют активный справочник |
| Отказ от особого времени суток 24:00 | Принято: нативные поля времени и 00:00 следующего дня; полные сутки доступны ручной длительностью |
| Библиотека графиков | Не включать: два режима простого столбчатого графика и таблица реализуемы встроенным SVG; отдельная библиотека нарушает состав из трёх файлов, а встраивание стороннего кода пока не оправдано объёмом задачи |
| Разрешить ES-модули при file:// | Не принято: загрузка внешних модулей при локальном открытии может блокироваться CORS; требование работать двойным щелчком важнее. Структурирование обычного JS явно предусмотрено |

Технические справочные источники для этих решений: [MDN — JavaScript modules, локальное тестирование и CORS](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules), [MDN — поведение localStorage при file:](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage), [MDN — ограничения хранилищ и QuotaExceededError](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria). Приведённые ограничения браузеров не заменяют фактическую проверку целевого окружения.
